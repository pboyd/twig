# Phase 1 Data Model: User Authentication

Source: `spec.md` (Key Entities, FR-008..FR-013, FR-019) and the approved design
`docs/plans/2026-05-19-auth-design.md`. Schema is applied by migration
`000003_auth`; access code is generated by `sqlc` from `db/queries/auth.sql`
and the modified `db/queries/task.sql`.

## Entity overview

```text
users (1) ──< (N) sessions
users (1) ──< (N) api_keys
users (1) ──< (N) tasks
```

A user owns sessions, API keys, and tasks. Deleting a user cascades to all
three. Sessions and API keys are credentials; tasks are the protected resource.

## Table: `users`

| Column          | Type                            | Constraints                         |
|-----------------|---------------------------------|-------------------------------------|
| `id`            | `BIGINT GENERATED ALWAYS AS IDENTITY` | primary key                   |
| `username`      | `TEXT`                          | `NOT NULL`, `UNIQUE`                |
| `password_hash` | `TEXT`                          | `NOT NULL` — bcrypt string, cost 12 |

Notes:
- `id` uses `BIGINT ... IDENTITY` to match the existing `tasks` table and map to
  Go `int64` (see research Decision 5).
- `username` uniqueness gives the identity rule for FR-019 (provisioning a name
  that already exists updates that row).
- `password_hash` never holds plaintext (FR-008).

## Table: `sessions`

| Column       | Type          | Constraints                                  |
|--------------|---------------|----------------------------------------------|
| `id`         | `TEXT`        | primary key — 32 random bytes, hex (64 chars)|
| `user_id`    | `BIGINT`      | `NOT NULL`, `REFERENCES users(id) ON DELETE CASCADE` |
| `created_at` | `TIMESTAMPTZ` | `NOT NULL`                                   |
| `expires_at` | `TIMESTAMPTZ` | `NOT NULL`                                   |

Notes:
- `id` is the session token itself and is used directly as the cookie value
  (research Decision 4). It is cryptographically random, so it is stored
  verbatim and looked up by primary key.
- `expires_at = created_at + lifetime`; default lifetime 30 days, configurable
  (FR-005).
- Index on `user_id` supports cascade and per-user cleanup.

### Session lifecycle

```text
            POST /auth/login (valid credentials)
                      │
                      ▼
   ┌───────────────────────────────────┐
   │ active: now < expires_at          │  ──► every request resolves user_id
   └───────────────────────────────────┘
        │                       │
  POST /auth/logout       now ≥ expires_at
        │                       │
        ▼                       ▼
   row deleted            expired: request rejected 401;
                          row may be deleted lazily
```

A session is valid only while a matching row exists **and** `now < expires_at`.
Logout deletes the row. An expired row grants nothing; it may be removed when
next encountered.

## Table: `api_keys`

| Column       | Type          | Constraints                                  |
|--------------|---------------|----------------------------------------------|
| `id`         | `BIGINT GENERATED ALWAYS AS IDENTITY` | primary key          |
| `user_id`    | `BIGINT`      | `NOT NULL`, `REFERENCES users(id) ON DELETE CASCADE` |
| `key_hash`   | `TEXT`        | `NOT NULL`, `UNIQUE` — SHA-256 hex of raw key|
| `label`      | `TEXT`        | nullable — human-readable note               |
| `created_at` | `TIMESTAMPTZ` | `NOT NULL`                                   |

Notes:
- The raw key (32 random bytes, hex) is shown once at provisioning and never
  stored; only its SHA-256 hash is persisted (FR-009).
- `key_hash` is `UNIQUE` so a presented key resolves to at most one row; lookup
  is by `key_hash`.
- Revocation = deleting the row (FR-011). No status column is needed.
- Index on `user_id` supports cascade.

### API key lifecycle

```text
provisioning ──► row created, raw key printed once
      │
      ▼
  active: every CLI request hashes the presented key, matches key_hash
      │
   row deleted (revoke / re-provision)
      │
      ▼
  revoked: next request fails to match → 401
```

## Table: `tasks` (modified)

Add one column to the existing table:

| Column      | Type     | Constraints                                          |
|-------------|----------|------------------------------------------------------|
| `user_id`   | `BIGINT` | `NOT NULL`, `REFERENCES users(id)` — owning user     |

Plus an index `tasks_user_id_idx` on `user_id`.

- Every task belongs to exactly one user (FR-012).
- Added `NOT NULL` directly — no pre-auth rows exist (research Decision 5).
- All existing columns (`id`, `name`, `description`, `due`, `parent_id`) are
  unchanged. `parent_id` still references `tasks(id)`; a task and its parent are
  always owned by the same user because every task query is `user_id`-scoped.

## Query changes

### `db/queries/auth.sql` (new)

| Query | Kind | Purpose |
|-------|------|---------|
| `CreateUser` | `:one` | Insert a user with `username`, `password_hash`. |
| `GetUserByUsername` | `:one` | Look up a user for login. |
| `UpdateUserPassword` | `:exec` | Reset password for an existing user (FR-019). |
| `CreateSession` | `:one` | Insert `id`, `user_id`, `created_at`, `expires_at`. |
| `GetSession` | `:one` | Fetch a session by `id` (middleware checks `expires_at`). |
| `DeleteSession` | `:exec` | Delete a session by `id` (logout). |
| `CreateApiKey` | `:one` | Insert `user_id`, `key_hash`, `label`, `created_at`. |
| `GetApiKeyByHash` | `:one` | Resolve a presented key hash to its `user_id`. |
| `DeleteApiKeysByUser` | `:exec` | Drop a user's keys before re-provisioning. |

### `db/queries/task.sql` (modified)

Every query becomes user-scoped (FR-013):

| Query | Change |
|-------|--------|
| `CreateTask` | Add `user_id` to the column list and `VALUES`. |
| `GetTask` | `WHERE id = $1 AND user_id = $2`. |
| `ListTasks` | `WHERE user_id = $1 ORDER BY id`. |
| `UpdateTask` | `WHERE id = $1 AND user_id = $6` (extra param). |
| `DeleteTask` | `WHERE id = $1 AND user_id = $2`. |
| `TaskExists` | `EXISTS (SELECT 1 FROM tasks WHERE id = $1 AND user_id = $2)`. |

A task owned by another user therefore returns no row — indistinguishable from
"not found" — so direct-ID probes across users fail closed (spec edge case).

## Generated Go types (sqlc)

`internal/db/models.go` is regenerated to add:

```go
type User struct {
    ID           int64
    Username     string
    PasswordHash string
}

type Session struct {
    ID        string
    UserID    int64
    CreatedAt pgtype.Timestamptz
    ExpiresAt pgtype.Timestamptz
}

type ApiKey struct {
    ID        int64
    UserID    int64
    KeyHash   string
    Label     pgtype.Text
    CreatedAt pgtype.Timestamptz
}
```

and `Task` gains `UserID int64`.

## Validation rules

| Rule | Where enforced |
|------|----------------|
| `username` unique | `users.username UNIQUE` constraint |
| Password never stored in plaintext | bcrypt hashing before `CreateUser` |
| API key never stored raw | SHA-256 hashing before `CreateApiKey` |
| Session rejected once expired | middleware compares `now` to `expires_at` |
| Task access scoped to owner | `user_id` predicate in every task query |
| Provisioning an existing user updates, not duplicates | `GetUserByUsername` → `UpdateUserPassword` + `DeleteApiKeysByUser` + `CreateApiKey` |
