# API Contract: PlanService (`plan.v1`)

This file is the source of truth for the PlanService API. During implementation it is copied to `services/todo/proto/plan/v1/plan.proto` and bindings are generated by `buf generate`.

## Proto file

```proto
syntax = "proto3";

package plan.v1;

option go_package = "github.com/pboyd/todo/services/todo/gen/plan/v1;planv1";

// PlanService manages day-scoped plan entries for the calling user.
service PlanService {
  // ListPlanEntries returns every entry on the given day, ordered by start_minute ascending.
  rpc ListPlanEntries(ListPlanEntriesRequest) returns (ListPlanEntriesResponse);

  // AddPlanTask appends an entry linked to a task. Server allocates the per-day id.
  rpc AddPlanTask(AddPlanTaskRequest) returns (AddPlanTaskResponse);

  // AddPlanEvent appends an entry not linked to a task (a name is required).
  rpc AddPlanEvent(AddPlanEventRequest) returns (AddPlanEventResponse);

  // RemovePlanEntry deletes the entry identified by (day, id).
  rpc RemovePlanEntry(RemovePlanEntryRequest) returns (RemovePlanEntryResponse);

  // RenamePlanEntry replaces the entry's display name.
  rpc RenamePlanEntry(RenamePlanEntryRequest) returns (RenamePlanEntryResponse);

  // MovePlanEntry changes start_minute and optionally duration_minute.
  rpc MovePlanEntry(MovePlanEntryRequest) returns (MovePlanEntryResponse);

  // ClearPlan removes every entry starting at or after start_minute on day; if an
  // entry straddles start_minute, its duration is shortened so it ends at start_minute.
  rpc ClearPlan(ClearPlanRequest) returns (ClearPlanResponse);
}

// PlanEntry is a single scheduled segment of one day. Identity within a user's
// data is (day, id). user_id is implicit from the authenticated caller and
// not carried on the wire.
message PlanEntry {
  // The day this entry belongs to, in YYYY-MM-DD.
  string day = 1;
  // Server-assigned, per-day sequential, never renumbered.
  int32 id = 2;
  // Optional link to a task. 0 (default) means no task.
  int64 task_id = 3;
  // Display name override. Empty string when omitted; clients should fall back
  // to the linked task's name in that case.
  string name = 4;
  // Minutes since local midnight on `day`. Range: 0..1439.
  int32 start_minute = 5;
  // Length of the entry, in minutes. > 0, and start_minute + duration_minute <= 1440.
  int32 duration_minute = 6;
}

message ListPlanEntriesRequest { string day = 1; }
message ListPlanEntriesResponse { repeated PlanEntry entries = 1; }

message AddPlanTaskRequest {
  string day = 1;
  int64 task_id = 2;
  int32 start_minute = 3;
  // 0 means "let the server choose": (estimate - completed) * 30 if positive, else 30.
  int32 duration_minute = 4;
}
message AddPlanTaskResponse { PlanEntry entry = 1; }

message AddPlanEventRequest {
  string day = 1;
  string name = 2;
  int32 start_minute = 3;
  // 0 means "use the 30-minute default".
  int32 duration_minute = 4;
}
message AddPlanEventResponse { PlanEntry entry = 1; }

message RemovePlanEntryRequest { string day = 1; int32 id = 2; }
message RemovePlanEntryResponse {}

message RenamePlanEntryRequest { string day = 1; int32 id = 2; string name = 3; }
message RenamePlanEntryResponse { PlanEntry entry = 1; }

message MovePlanEntryRequest {
  string day = 1;
  int32 id = 2;
  int32 start_minute = 3;
  // 0 means "keep the existing duration unchanged".
  int32 duration_minute = 4;
}
message MovePlanEntryResponse { PlanEntry entry = 1; }

message ClearPlanRequest { string day = 1; int32 start_minute = 2; }
message ClearPlanResponse {
  // Number of entries deleted outright (not counting the one that was trimmed, if any).
  int32 deleted_count = 1;
  // True iff exactly one entry was shortened to end at start_minute.
  bool trimmed_straddling_entry = 2;
}
```

## Per-RPC contract

### `ListPlanEntries(day)`

- Returns all of the caller's entries on `day`, ordered by `start_minute` ascending. An empty list is a valid response (an empty plan).
- `day` must be `YYYY-MM-DD`. Otherwise `InvalidArgument`.

### `AddPlanTask(day, task_id, start_minute, duration_minute)`

- Allocates the next per-day `id` = `COALESCE(MAX(id), 0) + 1` and inserts the entry inside one transaction that has already locked the day's existing rows.
- Default duration when the client sends `0`:
    - If the task has `estimate > 0` and `estimate - completed_pomodoros > 0`: `(estimate - completed) * 30`.
    - Otherwise: `30`.
- Errors:
    - `NotFound` — `task_id` does not exist for this user.
    - `InvalidArgument` — `start_minute` outside `[0, 1440)`; `duration_minute < 0`; `day` malformed; `start + duration > 1440`.
    - `FailedPrecondition` — the new interval would overlap an existing entry on the day. The error message names the conflicting entry's `id`.

### `AddPlanEvent(day, name, start_minute, duration_minute)`

- Identical id-allocation, locking, and overlap behaviour as `AddPlanTask`.
- `name` must be non-empty after trim and ≤255 characters; otherwise `InvalidArgument`.
- Default duration when the client sends `0`: `30`.

### `RemovePlanEntry(day, id)`

- Deletes the row. Other entries' `id`s are not renumbered (FR-003).
- Errors:
    - `NotFound` — no such `(day, id)` for this user.

### `RenamePlanEntry(day, id, name)`

- Updates `name` only.
- `name` must be non-empty after trim and ≤255 characters; otherwise `InvalidArgument`.
- Errors:
    - `NotFound` — no such `(day, id)`.

### `MovePlanEntry(day, id, start_minute, duration_minute)`

- Updates `start_minute`. Updates `duration_minute` iff the client sends a non-zero value; `0` means "keep current duration".
- Overlap and midnight-crossing checks run inside the same transaction that fetches the current row, against every *other* entry on the day.
- Errors:
    - `NotFound` — no such `(day, id)`.
    - `InvalidArgument` — out-of-range start or duration; `start + duration > 1440`.
    - `FailedPrecondition` — the proposed interval overlaps another entry. Error message names the conflicting entry's `id`.

### `ClearPlan(day, start_minute)`

- In one transaction:
    1. If exactly one entry straddles `start_minute` (i.e., `start < start_minute < start + duration`), shorten its `duration_minute` to `start_minute - start`.
    2. Delete every entry with `start >= start_minute` on `day`.
- Returns `deleted_count` (does **not** include the trimmed entry) and `trimmed_straddling_entry` (true iff step 1 occurred).
- Errors:
    - `InvalidArgument` — `start_minute` outside `[0, 1440)`; `day` malformed.
- `ClearPlan` on a day with no entries is a successful no-op returning `{ deleted_count: 0, trimmed_straddling_entry: false }`.

## CLI ↔ RPC mapping

| CLI invocation | RPC |
|---|---|
| `todo plan` | `ListPlanEntries(today)` → render grid |
| `todo plan --date Y-M-D` | `ListPlanEntries(Y-M-D)` → render grid |
| `todo plan task <id> <start> [dur]` | `AddPlanTask(today, id, parseStart(start), parseDur(dur or 0))` |
| `todo plan event <name> <start> [dur]` | `AddPlanEvent(today, name, parseStart(start), parseDur(dur or 0))` |
| `todo plan rm <n>` | `RemovePlanEntry(today, n)` |
| `todo plan rename <n> <name>` | `RenamePlanEntry(today, n, name)` |
| `todo plan mv <n> <start> [dur]` | `MovePlanEntry(today, n, parseStart(start), parseDur(dur or 0))` |
| `todo plan clear [start]` | `ClearPlan(today, parseStart(start or now))` |

The `--date YYYY-MM-DD` flag overrides "today" in every row above. `today` and `now` are computed from the CLI host's local clock and zone.
