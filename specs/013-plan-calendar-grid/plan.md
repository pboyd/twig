# Implementation Plan: Plan Calendar Grid View

**Branch**: `013-plan-calendar-grid` | **Date**: 2026-05-27 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/013-plan-calendar-grid/spec.md`

## Summary

Replace the current single-column inline grid renderer in `internal/cli/plan_grid.go` with a calendar-style renderer that draws each hour as a horizontal divider, splits each hour into four 15-minute text rows, and renders each plan entry as a heavy box-drawn rectangle aligned to its 15-minute snapped start/end. Adjacent entries share a single heavy border. The default visible window is 08:00–17:00, extended outward to contain any out-of-range entry. The calendar width adapts to the terminal. On today's date, a left-gutter marker is drawn at the current 15-minute row. When a plan entry references a completed task, its label is rendered with strikethrough (and dimmed on TTY).

Strikethrough requires per-entry completion status, which is not currently on the wire. We add a single `bool completed = 7` field to `PlanEntry` populated server-side from a join on the tasks table. This is the only contract change.

## Technical Context

**Language/Version**: Go 1.23 (existing module).

**Primary Dependencies**: ConnectRPC, pgx/v5, existing internal packages (`internal/cli`, `internal/handler`, `internal/db`).

**Storage**: PostgreSQL (no schema change; `tasks` table already carries completion state via `completed_at`).

**Testing**: standard `go test ./...`; golden-string assertions on rendered grid output in `internal/cli/plan_grid_test.go`.

**Target Platform**: Linux CLI (`todo plan`), rendered on the user's terminal.

**Project Type**: Single Go module with two binaries (server + CLI). This feature touches the CLI render layer and one server handler/query.

**Performance Goals**: Render under 10 ms for a typical day (≤50 entries). Not a hot path.

**Constraints**: Output must be valid UTF-8 with Unicode box-drawing characters; preserves existing exit codes; no new CLI flags introduced.

**Scale/Scope**: A single day's plan, typically <20 entries; the renderer scales linearly with `(window_hours * 4) + entries`.

## Constitution Check

No violations to track.
