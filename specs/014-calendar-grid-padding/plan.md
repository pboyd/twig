# Implementation Plan: Calendar Grid Padding & Gutter Refinement

**Branch**: `014-calendar-grid-padding` | **Date**: 2026-05-27 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/014-calendar-grid-padding/spec.md`

## Summary

A visual-only refinement of the calendar grid view introduced in feature 013. The hour grid (light horizontal hour lines and light left/right rails) becomes always-on across the full visible window. Every heavy entry box is inset by one column from each rail, so the heavy box reads as sitting "inside" the light grid. The gutter gains one extra space so the "now" marker is separated from the hour-label text. Total calendar width is unchanged; the new padding/gutter columns come out of the existing width budget, narrowing the box interior by ~2 columns. No data-model, API, or storage changes.

All work happens in `services/todo/internal/cli/plan_grid.go` and its test file.

## Phase 1 — Design

### Rendering rules (the implementable contract)

Per row in the visible window, in column order from left to right:

1. **Gutter**: hour label (`HH:MM` on hour rows, blank otherwise), then one space, then the now-marker column (the marker glyph on the current 15-minute row of today's plan; a blank space everywhere else). The rule that matters: on every row the rail's column index is identical, and on the now row the layout is `HH:MM` + space + marker + rail. The implementation uses whatever fixed gutter width matches the example in `spec.md`.

2. **Left rail**: `├` on hour rows, `│` on non-hour rows. Always drawn — never replaced by a heavy box character.

3. **Left padding column** (one column, between left rail and any heavy box):
   - On hour rows with no heavy box edge at this row: a single light `─` (continuation of the hour line).
   - On rows occupied by a heavy box (above, below, or beside): a single space (` `).

4. **Heavy box region** (when an entry is present at this row): one of:
   - Heavy top edge: `┏━━…━━┓` (or `┣━━…━━┫` when sharing a boundary with the entry above).
   - Heavy bottom edge: `┗━━…━━┛` (or `┣━━…━━┫` when sharing a boundary with the entry below).
   - Heavy interior row: `┃` … `┃` with label text (or blanks) between.

5. **Right padding column**: mirror of the left padding column.

6. **Right rail**: `┤` on hour rows, `│` on non-hour rows.

For rows with no heavy box at all (empty rows inside an hour, or any row in an entry-free hour):
- Hour row: `├` + `─` × W + `┤` (where W = calendar_width − 2).
- Non-hour row: `│` + (space × W) + `│`.

### Backward compatibility with the 013 shared-border rule

The shared-border rule from 013 (back-to-back entries sharing one heavy horizontal line) is unchanged. The heavy T-junctions (`┣`, `┫`) at the shared boundary butt against a single light `─` on each side, with the light hour line stopping one column before the heavy junction — identical to the top/bottom-edge case.

### Test plan (executable contract)

`plan_grid_test.go` will be updated and extended:

1. **Update existing goldens**: every existing test's expected output is regenerated to reflect (a) one-column padding between rails and heavy boxes, (b) always-on hour lines/rails over the full window, (c) the extra gutter space.
2. **New test — always-on grid through a multi-hour entry**: a single 2-hour entry; assert every hour row between start and end shows the light hour line continuing on both sides of the heavy box, and that the heavy verticals on non-hour rows sit one column inside the rails.
3. **New test — empty hours show full grid**: a day with one 1-hour entry sandwiched between empty hours; assert the empty hours render with full `├─…─┤` hour lines and `│ … │` non-hour rows.
4. **New test — gutter alignment**: today's plan vs a non-today plan rendered at the same hour; assert the left-rail column index is identical and that the marker glyph appears in the marker column on today, blank on non-today.
5. **New test — off-hour box edge padding**: an entry from `09:15` to `09:45`; assert the heavy top and bottom rows still have a one-column space (not a heavy char, not a light dash) between each rail and the box.
6. **New test — shared border + padding interaction**: two back-to-back entries (e.g. `13:00–13:15` and `13:15–13:30`); assert one `┣ ━ … ━ ┫` line at `:15` with light-dash padding on each side.
