# Implementation Plan: Show Scheduled Days in Task Details

**Branch**: `042-scheduled-task-display` | **Date**: 2026-06-07 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/042-scheduled-task-display/spec.md`

## Summary

Add a `Scheduled for: <YYYY-MM-DD[, ...]>` line to the TUI Tasks-tab details pane listing the current/future days a task is placed in the daily plan (today-or-later by the user's **local** date; past days hidden; no line when none). The plan service is day-scoped today, so the approach adds one reverse-lookup RPC `PlanService.ListScheduledDays(from_day)` backed by a single `SELECT DISTINCT task_id, day FROM plan_entries WHERE ... AND day >= from_day`. The TUI fetches this in bulk into a `map[int64][]string` (refreshed with task loads / Tasks-tab switch / send-to-plan) and renders the line synchronously in `renderDetails`.

## Technical Context

**Language/Version**: Go 1.x (CLI/TUI root module + `services/twig` server module); both depend on `api/` via `replace`.

**Primary Dependencies**: ConnectRPC + protobuf (`buf`/`make proto`), Bubble Tea / lipgloss (TUI), pgx/v5 + sqlc (server DB), golang-migrate (none needed here).

**Storage**: PostgreSQL, existing `plan_entries` table. **No migration** — read-only feature.

**Testing**: `go test ./...` (root: TUI render/wiring with fakes, no DB); `cd services/twig && go test ./...` (handler test gated on `DATABASE_URL`, skipped when unset).

**Target Platform**: Linux/macOS terminal (TUI on a TTY) talking to the HTTP/2 server.

**Project Type**: Multi-module full-stack (CLI/TUI client + ConnectRPC server + shared proto). Not web/mobile.

**Performance Goals**: Details pane renders synchronously per cursor move with no added round trip; one bulk schedule fetch per task-list load. Query is a single indexed read.

**Constraints**: TUI-only surface; no change to CLI or web clients; no change to `TaskService`; "past" cutoff is the client's **local** date.

**Scale/Scope**: Personal todo scale (hundreds of tasks/plan entries per user). Response bounded to scheduled tasks × today-or-future days.

## Phase 0 — Research

See [research.md](./research.md). Key decisions:
1. **Server-side reverse query (new RPC)** rather than client-side day scanning — required by the "all future days, no horizon" rule.
2. **Bulk fetch into a Model map**, refreshed with task loads / Tasks-tab switch / `ctrl+p` — avoids per-selection round trips and keeps render synchronous.
3. **Local-date `from_day` cutoff** — from the spec clarification; intentionally diverges from the UTC snooze line.
4. **Render via existing details-pane conventions** — `labelStyle`, comma-space join, omit when empty, both styled and plain paths.

All NEEDS CLARIFICATION resolved (the one spec-level ambiguity was answered in `/speckit-clarify`).
